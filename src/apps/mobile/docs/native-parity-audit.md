# 鸿蒙、Android 与 iOS 对齐核对

以当前工作区的 ArkUI 实现为基线，包含本机 GenUI 模型设置和输入区的待提交优化。Android 使用 Compose，iOS 使用 SwiftUI，三端从同一份移动端设计契约生成 UI tokens。GenUI 文档使用同一份 OpenUI Lang 组件库、模型工具协议与产品内置文档运行时。模型和文档状态由各端宿主管理。

| 已登录首页与侧栏 | 紧凑最近会话、设备选择、已保存远程工作区、文件分栏和侧栏手势。远程首页只保留左上角菜单入口，会话副标题显示完整工作区路径，主内容在可用高度内居中 | Android、iOS 已有同类产品路径和设计 tokens。两端远程首页已移除额外的 `OpenBitFun` 标题栏，菜单入口改为鸿蒙同位置的透明浮动控件，会话副标题统一使用工作区完整路径，iOS 同步补齐可用高度内居中布局 | 核对最近页尺寸、空态、首启复原、折叠/分栏、设备切换以及离线重连 |

| 设备版本兼容性 | 鸿蒙使用 Relay 返回的 `compatible` 拒绝确认不兼容的设备，旧 Relay 省略标记时按在线状态处理。连接页和账号页现直接显示兼容性原因，侧栏使用错误状态 | Android 和 iOS 原先多处只检查在线状态。共享层现在统一校验设备的手动选择、默认选择、已保存目标恢复及按设备创建会话和工作区。在线但不兼容的桌面继续显示于连接页、账号页、创建会话的设备列表和侧栏。刷新发现当前目标不兼容时停止绑定，保留已保存目标和工作区缓存。设备恢复兼容后可重新建立连接 | 使用真实 Relay 验证版本变更、连接撤销和恢复。鸿蒙新 HAP 缺少签名配置，待把新版本装到模拟器复核不兼容状态 |
| 对话和远控 | 输入区、历史锚点、复制与回退、工具审批/问询、队列、模型角色、图片和终端 | Android、iOS 和共享 KMP 已覆盖同一套流式消息、思考块、结构化工具块、折叠工具汇总、子任务、文件预览、审批问询、队列和失败状态。命令芯片、技能目录筛选、会话用量分组、压缩/初始化回执、技能 token、目标预填充和 staged rollback 已接入 Android Compose 与 iOS SwiftUI。两端回退会先把目标消息及后续行显示为 ghost，提供确认、关闭和回退后发送，shared 层统一 host_invoke、严格校验 `session_rolled_back`、失败重同步和回退后发送草稿恢复。Android 与鸿蒙真实会话曾对照 `/Users/user/workspace/BitFun`，iOS 流式/工具/子任务回归 13/13 通过 | 仍需在三端同一兼容 host 上逐项实发消息、等待回复、执行命令芯片和确认回退结果。老 host 的技能目录/用量命令超时或拒绝必须显示可重试状态 |
| 设置与通知 | 窄屏设置从底部打开，展开后的竖屏和横屏由 ArkUI 居中显示 480 × 560 的面板。通用页有原生、极光、蓝图、青瓷四种小应用风格。首次通知引导用系统授权 | Android、iOS 原先在宽屏将设置靠右。现在宽屏使用与鸿蒙同尺寸的居中面板，内容超高时可滚动。Android 设置首页改用固定标题栏。两端在容器切换时保留当前设置页和模型角色 | 轻量窗口、真机折叠、动态字号、键盘开启时的布局和系统授权状态仍需复核。三端设置的其他子页及小应用风格仍需逐项实屏核对 |
| 受控设备的模型默认值 | 在当前在线且已连接的设备行进入「模型设置」，可配置主力、快速和多模态模型。快速模型可跟随主力，多模态模型可留空。旧桌端显示升级提示 | Android、iOS 原先只有会话级选模。现已接入设备行入口和同一设置面板内的角色页。仅支持的桌端会收到这些设置请求。候选按桌端顺序展示，按启用状态和角色能力筛选。保存前重新读取其余槽位，发送三个可管理槽位，读回后再更新显示。断开连接或更换设备会使旧结果失效 | 用实际登录的兼容桌端复核并发修改和最终持久化 |

## 本机 GenUI

| 链路 | 鸿蒙基线 | Android / iOS 当前实现 | 待验收或差距 |
| --- | --- | --- | --- |
| 入口与会话 | 侧栏创建小应用。首次发送才产生记录，列表按最后消息时间排序，显示当前会话、生成状态和长按删除。会话操作菜单可打开创作记录，已保存会话可在标题下方改名。生成后可回到对话或从应用馆独立打开 | 两端按相同规则呈现创作记录。返回列表时保留当前选中项和正在生成的请求，空白创作入口可恢复工作草稿。旧版本未记录的时间留空。改名保留排序时间，后续生成不覆盖手动标题。两端保留对端发送图片入口，位于列表右上角「更多」 | 横屏、系统大字、快速切换后的键盘，以及鸿蒙与其他系统的原生协作待验收 |
| 消息与生成卡片 | 用户气泡限制宽度，长消息以八行或 360 个 UTF-16 单元为界，带「全文」入口。助手回复渲染 Markdown，可复制富文本、Markdown 和纯文本。生成卡片包含缩略图、标题、状态及打开动作 | Android、iOS 使用相同的气泡宽度、消息间距和卡片尺寸，显示新消息的本地时间。长气泡可打开可选中文本面板或复制原文。正文滚动时经过固定的会话栏和输入区。小应用可打开且极光入场动画结束后自动保存页面顶部的方形预览。旧消息缺少的时间留空 | 复杂 Markdown 富文本、动态字号和折痕位置变化仍需核对。鸿蒙参考包的卡片会显示旧的等待状态，当前源码已修正卡片刷新条件 |
| 生成时阅读历史 | 在底部时跟随流式回复。回看历史时保留当前视口，手动回到底部或发送新一轮后继续跟随 | Android 和 iOS 沿用各自对话的原生滚动控制，在流式内容增长和结尾落盘时保留阅读位置。实际接收一条新输入后恢复跟随 | 鸿蒙参考包在同一次会话中复用活动回复 ID，第二轮发送后不会恢复跟随。当前鸿蒙源码改用生成轮次 ID，同一轮更新使用同一 ID，待签名包实屏复测 |
| 创作输入区 | 模型和主操作始终有独立一行。未聚焦的单行草稿使用省略预览，聚焦或输入换行后可见最多四行。已选模型排在弹层第一项，切换模型时键盘继续可用，打开管理模型时收起键盘。已配置模型提交回执只清除提交的草稿版本 | 两端调整了输入框折叠、编辑和多行展示。选模菜单在模型入口上方展开。用实际模型名称作主标签，保留用户填写的配置名称，并使用 48 单位触控区内的 32 单位发送或停止圆面。iOS 使用原生多行编辑器应用 24 点行高。已配置模型接受发送后继续编辑同一个输入框，进入生成应用时键盘随对话退出 | 系统输入法、动态字号、横屏极小可用高度以及拼音和多候选输入仍需单独核对 |
| 模型及凭据 | 手机使用底部面板，折叠屏展开后使用居中面板。面板内查看、添加和编辑模型，发现结果以标签呈现。独立存储凭据，会话绑定指定模型，删除后提示重配，可导入旧配置 | 两端曾在打开时固定面板形态。现在随窗口宽度切换底部或居中面板，保留活动表单、字段、模型发现结果及写入回执。新输入的密钥置于当前编辑器的内存中。同地址编辑可复用原密钥。首次配置可选已保存的模型，或在新模型与会话的绑定持久化后关闭面板并保留草稿。接入 OpenAI 兼容接口和 Anthropic Messages 工具流 | 手机面板上缘、阴影、系统遮罩和密钥遮挡样式仍有实屏差异。历史配置导入和实际服务商覆盖待验收 |
| 生成与编辑 | SSE 文本、增量解码 OpenUI source、流式预览、取消。支持 patch 和候选校验。候选完整落盘后显示「正在准备」，校验结果更新同一张卡片。可修复的源码缺陷每个应用最多自动重试两次，持久化尝试次数和诊断，同一失败只重试一次。重开会话时重新检查已写入的候选。自动修正提示及每次候选的结果保留在会话里。仅有未验证项且存储回读一致时，应用可使用 | 两端在首次生成源码完整写入或编辑补丁成功合并后，从持久化检查点展示候选卡片。卡片可打开当前校验，完成后以原时间和顺序显示结果。发起自动修复前，同一次写入保存结果卡片、自动修正消息和去重预算。重开会话时续做本机检查。探针未报告时，仍在源码、磁盘回读和数据迁移校验后显示「可以使用」 | 各外观下的失败页，以及鸿蒙新安装包的即时刷新和中断恢复待验收 |
| 已生成文档与状态 | 原生浮层控制、OpenUI Lang 运行时、按应用与源码版本保存状态、冲突处理、回到助手继续。源码更新前校验已编辑数据能否迁移 | 两端按已声明状态的键和类型校验迁移。兼容时合并初始值与用户已编辑值。不兼容或复开前数据发生变动时保留上一版及其数据。同一源码版本号的不同应用按各自挂载的状态初始化 | 用户手动解决不兼容迁移，以及 JS 崩溃后的恢复待验收 |
| 日历与设备 | 日历增改查删、创建回执、触觉和应用方向请求 | 两端接入本机触觉、方向请求与退出恢复。GenUI 可创建、更新、查询和删除 OpenBitFun 日历内的日程，显示编号或查询条数。删除动作兼容旧文档的对象参数 | iOS 使用独立编号对应 EventKit 日程。旧测试版本写入且未建立编号映射的日程仍需迁移验证。不同姿态下的旋转待核对 |
| 手势计分与触发器 | 前置相机预览、本机骨架识别、左右手和双手动作、状态反馈及隐藏后停止 | Android 采用 CameraX 和 ML Kit，iOS 采用 AVFoundation 和 Vision。共用鸿蒙的阈值、连续两帧和放手重新触发规则，按应用、源码版本及订阅 ID 路由。相机浮层的尺寸、位置和徽标样式由同一组 tokens 生成。三个宿主均以相机流的实际启用状态控制徽标 | 用实体设备验证 iOS 和鸿蒙的实时动作识别、左右手方向、横屏朝向及相机占用冲突后的恢复 |
| 跨设备取材 | ServiceCollaborationKit 发现设备并呈现对端许可，支持远端拍照、扫描一页和选一张图片。收到的 JPEG 属于当前小应用 | Android、iOS 使用各自的系统局域网发现服务。发起端从附近设备列表选择对端，双方确认匹配的验证码后，发送端通过原生相机、扫描器或图库取材，并沿已确认的同一条加密连接回传。图片存入当前小应用，重新打开后恢复。扫码和手动连接码可作为备用方式。AOSP 模拟器在缺少 Play services 文档扫描后端时走原生相机回退 | 按当前验收范围暂不要求鸿蒙 ServiceCollaborationKit。Android 和 iOS 的发现要求发送方打开接收取材请求的页面、允许本地网络并连接同一支持 IPv4 的局域网。图库和拍照已在模拟器桥接流程验证，三系统互通、真机发现、扫描回传待验收。Android 扫描依赖 Google Play 服务 |
| 图片与外部资源 | 宿主图片搜索、白名单图片代理、缓存、静态和动态 3D 图标与协作图片 | Android、iOS 接入 360、百度、Wikipedia 和 Wikimedia，搜索词和已下载图片留在本机缓存。两端按固定版本加载 Fluent Emoji 静态图标和动态封面。文档经宿主读取图片，图片来源限定为搜索服务的已知图片域 | 第三方图片域覆盖、网络失败重试和图库缩略图更新待核对 |
| 诊断 | 检查库和设计规格、预览探针、状态迁移检查和失败原因。日志记录未验证的检查项，正常应用卡片显示「可以使用」 | 两端挂载同一版本清单，复用运行时探针与状态声明，等待当前挂载完成解析后测量。基础设施超时和无法执行的检查以未验证结果落盘。运行时明确报告契约不匹配时，按鸿蒙判为失败 | 诊断报告的字段、日志和各异常场景的覆盖范围待继续对照 |

## 验收口径

三端应使用同一场景、语言、外观和逻辑窗口宽度。截图标记模拟器与场景，用实际交互验证返回、状态重开和错误恢复。系统状态栏、安全区、键盘、授权弹窗与桌面由平台绘制。内置工具、生成内容与远程控制分别使用离线文档、可重复的模型工具流和真实兼容 host 验证。视觉截图用于界面核对，远程权限及持久化必须由操作结果确认。

根目录运行 `pnpm run prepare:assets` 可构建包含 GenUI 文档的原生资源。`pnpm run mobile:ui:preview` 启动三端比较页。截图保存在本地，目录命名见 [模拟器截图说明](../design-system/preview/snapshots/README.md)。

| 证据 | 已观察的结果 | 核对边界 |
| --- | --- | --- |

### 同一模型输出的模拟器核对

在开发机运行 `node tests/fixtures/local-genui-model.mjs`。模型名称为
`parity-fixture`，API 密钥字段填入任意测试占位值。使用 Android
`adb reverse tcp:39172 tcp:39172` 和鸿蒙 `hdc rport tcp:39172 tcp:39172`
建立回环端口映射，再使用 `http://127.0.0.1:39172` 创建测试模型。iOS
模拟器直接使用开发机回环地址。三台设备输入相同的测试提示词，查看
「三端创作核对」文档，可继续验证返回、加入小应用馆、重新打开与主题切换。

iOS UI 测试 `MobileParityUITests/testLocalGenUiWithFixtureProvider` 读取
`OPENBITFUN_GENUI_FIXTURE_URL`，通过 `xcodebuild test` 可将该变量以
`TEST_RUNNER_OPENBITFUN_GENUI_FIXTURE_URL` 传给测试进程。

测试服务也返回 `parity-fast` 和 `parity-vision`。在创作输入区输入草稿后进入
「管理模型」，添加测试配置并点「获取模型列表」，选择 `parity-fast` 后保存。
检查当前模型、退出面板后保留的草稿和发送后打开的「三端创作核对」。
重新编辑当前模型可用保存的密钥再次拉取列表。iOS 的
`MobileParityUITests/testLocalGenUiModelSheetKeepsDraftAndUsesDiscoveredModel`
覆盖这条链路。共享测试 `LocalGenUiModelStoreTest` 还覆盖删除后选择模型、改地址时
凭据失效、会话绑定写入失败时回滚新配置，以及旧记录和工作草稿的读取。

核对面板的窗口变化时，在「添加模型」填入未保存的配置并获取列表，选择
`parity-vision` 后保持面板打开。本次 Android 模拟器用
`adb shell wm size 2040x2400` 扩大视口，再用 `adb shell wm size reset`
恢复。鸿蒙折叠模拟器可用 `hdc shell hidumper -s 4607 -a -y` 展开和
`hdc shell hidumper -s 4607 -a -p` 折叠。iOS 的
`MobileParityUITests/testLocalGenUiModelPanelAdaptsWithoutLosingEditor`
在 iPhone 和 iPad 上旋转两次，核对面板形态、未保存的字段和模型发现结果，
并检查取消后重开是空表单。

创作输入区复测时输入两行草稿 `ComposerParityDraft` 和 `Keep the second line`。
在软键盘开启时点当前模型，确认选中项在首行，菜单位于模型按钮上方。
选择另一配置后检查键盘和完整草稿，再收起键盘检查两行仍可见。
iOS 的 `MobileParityUITests/testLocalGenUiComposerKeepsTheKeyboardDuringModelSelection`
覆盖这条链路。

发送 `ScrollFollowResume` 时保持软键盘开启，等待看到 `ScrollResumeTail`。
检查输入框已清空，从键盘直接输入 `Continue with a fresh draft`，再添加五行
文本。检查编辑框高度限制在四行并保留六行原文。发送后检查已生成应用显示并退出键盘。iOS 的
`MobileParityUITests/testLocalGenUiTextReplyKeepsTheEditorFocusedAfterAcceptingTheDraft`
覆盖发送与继续编辑。

依次在两个新创作会话发送 `HistoryParityAlpha` 和 `HistoryParityBeta`，在「三端记录甲」
续写 `HistoryParityAlphaFollowUp` 后立即返回列表。甲应移动到顶部并标记为当前会话。
等创作结束后重开甲，查看原回复和续写回复，再长按乙执行删除。iOS 的
`MobileParityUITests/testLocalGenUiCreationHistoryKeepsWorkingDraftAndSortsByActivity`
还验证未发送的草稿可恢复且不会增加列表记录。

输入 `FirstFailureParity` 生成「三端首轮失败核对」。固定模型返回未知根组件，自动
修复仍返回同一缺陷。看到「没有生成成功」后返回对话，核对两张失败卡片之间的
一条「刚才的应用有点问题，正在自动修正」。冷启动后从创作记录再次打开卡片。
回到同一会话发送 `FirstFailureParityRecover`，确认同一应用通过校验，保留两张失败卡片并
新增一张可用卡片。iOS 的
`MobileParityUITests/testLocalGenUiFirstValidationFailureCanBeReopenedAndCreatedAgain`
覆盖这条链路。

发送 `RepairParityCreate` 生成「三端修复核对」，初始文档的未知根组件应触发自动修复。
在修复结果中点击「计数加一」，返回会话发送 `RepairParityReject`。服务重复返回同一
缺陷，应用应继续使用已验证的旧源码和计数 1。再发送 `RepairParityMigration` 将计数
声明改成字符串，检查不兼容提示和原数据。iOS 测试
`MobileParityUITests/testLocalGenUiRepairsFailedRenderAndKeepsThePreviousWorkingState` 覆盖三步。

`CheckpointParityBase` 生成「三端恢复核对」。把计数改为 1 后发送
`CheckpointParityUpdate`，应将「原有版本」改为「中断后恢复的版本」并保留计数。
iOS 测试 `MobileParityUITests/testLocalGenUiResumesVerificationAfterProcessTermination`
在复开检查暂停期间返回会话，核对更新版卡片显示「正在准备」，然后终止应用。
重进会话后，应在原位置看到更新后的卡片，总数仍是两张。也可在
Android 调试包的启动 Intent 添加布尔参数 `openbitfun.test.holdGenUiReopen`，
在检查点写入后执行 `adb shell am force-stop com.openbitfun.mobile.debug`，再用无参数启动
并进入同一会话。创作记录入口位于会话操作菜单，点会话标题可打开行内编辑。

在同一调试参数下保留进程运行，让复开探针超时。先生成基础应用并把计数改为 1，
再发送 `CheckpointParityUpdate`。校验期间可从候选卡片返回应用。两次完成后都应显示「可以使用」，重启后应可从
会话打开更新版，计数仍为 1。iOS 测试
`MobileParityUITests/testLocalGenUiReopenProbeTimeoutKeepsAppAndUserData` 覆盖该流程。
共享核心使用虚拟时间额外覆盖首次渲染和复开探针均未报告、用户数据结构无法确认，
以及复开探针明确报错的结果。

输入 `InsetsParityLandscape` 打开「三端安全区核对」，点击「窗口计数加一」，再返回会话。
横屏下该遮挡的一侧从安全区边缘摆放浮动控件，无遮挡的一侧保留 12 个逻辑单位。
Android 使用模拟缺口验证后恢复原设备设置。iOS 的
`MobileParityUITests/testLocalGenUiFloatingControlsRespectLandscapeSafeAreas` 同时检查
旋转时页面留在前台、浮动控件的大小与高度，以及横屏交互。

输入 `TranscriptParityFixture` 生成「三端会话卡片核对」。返回对话，查看两条消息的时间、
已生成应用卡片和助手回复旁的复制图标。选择「复制 Markdown」后应得到
`核对：**保留格式**与原文。`。iOS 的
`MobileParityUITests/testLocalGenUiTranscriptCardsTimesAndCopyFormats` 覆盖卡片、时间、
三个复制选项和再次打开已生成应用。

发送以 `LongMessageParityFixture` 开头、超过 360 个字符的消息可生成「三端长消息核对」。
返回对话后滚动到用户气泡，打开「全文」，再返回并确认草稿、气泡位置和输入区仍在。
iOS 的 `MobileParityUITests/testLocalGenUiLongMessagePreservesDraftAndTranscriptPosition`
覆盖这个往返流程。

在新会话发送 `ScrollFollowSeed original reading position` 取得长回复，再发送
`ScrollFollowStreamFixture`。回复稍后继续增长，等待期间滚回第一条用户气泡。
检查回复结束后气泡仍留在原位置。发送 `ScrollFollowResume` 后应看到末尾的
`ScrollResumeTail`。iOS 的
`MobileParityUITests/testLocalGenUiStreamingPreservesReadingPositionThenFollowsNewTurn`
覆盖这条链路。

输入 `Verify calendar actions` 可生成「三端日历核对」。授权模拟器应用访问
日历后，添加测试日程，将回执编号填入文档，再更新、查询和删除。查询范围为
2040 年 6 月 19 日 UTC，删除后条数应恢复到新增前的基线。iOS 的

输入 `PhotoParityFixture` 生成「三端图片核对」。在联网环境下，三端加载
`Tangerine` 的搜索结果以及 🍊 的 Fluent Emoji 3D 图标。Android、iOS 的
缓存入口由各自的 WebView 宿主解析，同一份文档引用使用鸿蒙已有的宿主地址格式。

输入 `GestureParityFixture` 生成「三端手势核对」。点击「开启手势记分」

可用 `-camera-front imagefile:<fixture.jpg>` 为 CameraX 提供可重复的图像输入。

输入 `DeviceImageParityFixture` 生成「三端取材核对」。在接收端选择
来自其他设备的图库、相机或扫描，保持接收面板在前台。在另一台 OpenBitFun

选择一张图片并确认发送。连接码在成功接收、关闭面板、离开前台或三分钟后失效。

`MobileParityUITests/testLocalGenUiCrossDeviceImage` 默认验证打开和取消接收。
添加 `TEST_RUNNER_OPENBITFUN_GENUI_LIVE_IMAGE_TRANSFER=1` 后等待另一台设备实际发送，

需要使用开发机端口转发。真机在同一局域网中直接连接。

附近设备路径使用 `TEST_RUNNER_OPENBITFUN_GENUI_LIVE_NEARBY=1`。在第二台 iOS
模拟器导入测试图片并运行 `testLocalGenUiNearbySender`，在发起端模拟器运行
`testLocalGenUiCrossDeviceImage`。配对需要两个用例同时驻留前台。Android 在启用
本地网络权限的 API 37 模拟器运行 `GenUiNearbyImagesTest`。

跨模拟器测试时，在 Android 运行 `GenUiNearbyImagesTest#sendGalleryImageToNearbySimulator`
并传入仪器参数 `-e genuiNearbyBridge true`。该用例发布实际 Android 发送端地址，打开系统
图库并发送独立相簿中的测试图。在开发机运行
`python3 tests/fixtures/genui-nearby-simulator-bridge.py --serial <Android 模拟器> --host <开发机局域网 IPv4>`，
然后在 iOS 发起端运行附近设备用例。桥接转发发现记录和加密字节流，双方确认及图片持久化由 App 完成。
[Android Emulator 网络地址空间](https://developer.android.com/studio/run/emulator-networking-address)

相机入口使用同一桥接命令，并将测试类改为
`GenUiNearbyImagesTest#sendCameraImageToNearbySimulator`。API 37 模拟器使用启动参数
`-camera-front imagefile:<fixture.jpg>`，用例点击系统相机快门和完成按钮，再等待图片送达回执。

附近设备验证码流程请求 `photo` 类型。

反向核对时，在 iPad 导入测试照片并运行 `testLocalGenUiNearbySender`。在同一开发机启动模型夹具，
给已安装调试包与测试 APK 的 Android 模拟器映射模型端口 `adb reverse tcp:39172 tcp:39172`。
运行 `python3 tests/fixtures/genui-nearby-simulator-bridge.py --serial <Android 模拟器> --ios-sender iPad`。
脚本读取 iPad 的 Bonjour 记录，在临时回环端口转发加密连接，再启动 `receiveGalleryImageFromNearbySimulator`。
接收用例创建夹具会话，确认图片可以从文档专属存储读取并解码，然后关闭并重新打开文档检查同一张图。

Android 用 NSD 注册和发现发送端，iOS 用 Bonjour。附近设备广播包含设备名称、地址和端口。
双方确认验证码后，发起连接用于传输加密图片和送达回执。
